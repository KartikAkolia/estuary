keyTerms:
  - term: "Protocol"
    definition: "An agreed set of rules that governs how devices format, transmit, and interpret data exchanged over a network."
  - term: "OSI model"
    definition: "A seven-layer reference model (ISO/IEC 7498-1) describing the functions a network system performs, from physical transmission up to the application layer — used to reason about and troubleshoot networking regardless of the actual protocol stack in use."
  - term: "IP routing"
    definition: "The process by which a router selects a path to forward a packet toward its destination network, based on its routing table."
  - term: "LAN / WAN"
    definition: "A Local Area Network covers a small geographic area (e.g. one building); a Wide Area Network connects LANs across larger distances, typically via a third-party carrier."
  - term: "Operating system"
    definition: "The system software that manages a computer's hardware resources and provides common services to application programs."

indepth:
  - heading: "Why networks are split into layers at all"
    body: >
      Two computers talking to each other actually have to solve a stack of
      separate problems: how to send raw electrical or radio signals down a
      wire or through the air, how to tell where one chunk of data ends and
      the next begins, how to find a path across many connected networks,
      and how to make sense of the actual message once it arrives. Rather
      than solving all of that in one tangled piece of software, networking
      is split into layers, each responsible for one problem and each only
      talking to the layers directly above and below it. This is what the
      OSI model formalises — a seven-layer reference picture, from the
      Physical layer at the bottom (the actual cable or radio signal) up to
      the Application layer at the top (the actual app, like a browser or
      email client).
  - heading: "Walking the stack: sending an email"
    body: >
      A concrete example makes the seven layers less abstract. When you hit
      send on an email, the Application layer hands off the message; the
      Presentation layer formats and, if needed, encrypts it; the Session
      layer keeps track of the ongoing conversation between your device and
      the mail server; the Transport layer chops the message into
      manageable segments and numbers them so they can be reassembled in
      order; the Network layer works out a path across the internet for
      each packet; the Data Link layer wraps each packet with local
      addressing (like a MAC address) for the next hop; and the Physical
      layer is what actually pushes the bits down the wire or over Wi-Fi.
      The receiving computer runs the exact same process in reverse, layer
      by layer, until the email lands in an inbox as a readable message
      again.
  - heading: "LAN vs. WAN — scale, not just distance"
    body: >
      A Local Area Network is a network confined to one site — a home, an
      office floor, a school building — usually owned and managed by
      whoever's using it. A Wide Area Network stitches multiple LANs
      together over a much larger distance, and typically depends on a
      third-party carrier's infrastructure (the phone network, fibre
      backbones, satellite links) to make the long-distance hop, since no
      single organisation usually owns cable that spans a country. The
      internet itself is best thought of as a WAN of WANs — a huge,
      loosely coordinated network of networks, all agreeing to speak the
      same routing protocols so a packet can hop from a home LAN in one
      country to a server on the other side of the world.
  - heading: "What a protocol actually buys you"
    body: >
      A protocol is just an agreed rulebook — both ends of a connection
      follow the same rules for formatting, sending, and interpreting data,
      so a device from one manufacturer can talk to a device from a
      completely different one without ever having been designed with each
      other in mind. Standards bodies (like the IETF, who publish RFCs —
      Requests for Comments — that become the internet's actual technical
      standards) exist specifically so no single company gets to unilaterally
      decide how the whole internet works.
